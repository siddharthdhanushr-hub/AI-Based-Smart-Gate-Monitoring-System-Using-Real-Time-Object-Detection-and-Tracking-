# AI-Based Smart Gate Monitoring System Using Real-Time Object Detection and Tracking

## 1. Project Overview & Mission
The **AI-Based Smart Gate Monitoring System** is a real-time computer vision and IoT analytics platform designed for monitoring campus/facility gate traffic. The system detects individuals and vehicles (cars, motorcycles, buses, trucks, bicycles), tracks them across frames with unique track IDs, identifies directional movement across a configurable virtual gate line (Entry vs. Exit), persists events in an SQLite database, and streams live telemetry, telemetry statistics, and video feeds to a React dashboard.

## 4. Module Interface Contracts

### 4.1. Detection & Tracking Output Contract (Chandrashekar $\rightarrow$ Dhanush)
Every detection/tracking pipeline cycle must emit tracked objects conforming strictly to the following dictionary/JSON schema:

```json
{
  "track_id": 12,
  "class_id": 0,
  "class_name": "person",
  "confidence": 0.92,
  "bbox": [100, 120, 240, 400],
  "center": [170, 260]
}
```

- **`track_id`** (`int`): Unique, persistent tracking ID generated by the tracking algorithm (e.g., DeepSORT / ByteTrack). Negative or `null` values indicate untracked raw detections.
- **`class_id`** (`int`): Zero-indexed category identifier (`0`: person, `1`: bicycle, `2`: car, `3`: motorcycle, `5`: bus, `7`: truck).
- **`class_name`** (`str`): Lowercase canonical name (`"person"`, `"bicycle"`, `"car"`, `"motorcycle"`, `"bus"`, `"truck"`).
- **`confidence`** (`float`): Detection confidence score rounded to 4 decimal places ($0.0 \le \text{confidence} \le 1.0$).
- **`bbox`** (`List[int]`): 4-element integer array in `[x1, y1, x2, y2]` format representing the bounding box pixel coordinates in frame space ($x_1 < x_2$, $y_1 < y_2$).
- **`center`** (`List[int]`): 2-element integer array `[cx, cy]` representing the centroid or bottom-center base of the bounding box used for virtual gate line crossing calculations:
  $$\text{cx} = \left\lfloor\frac{x_1 + x_2}{2}\right\rfloor, \quad \text{cy} = \left\lfloor\frac{y_1 + y_2}{2}\right\rfloor \quad (\text{or bottom center } y_2)$$

### 4.2. Model Loading Interface
The backend and CV modules interact with detection weights via a unified `ModelLoader` interface:
```python
from backend.app.detection.model_loader import ModelLoader

# Supports loading both baseline YOLOv8n and fine-tuned gate weights
detector = ModelLoader.load_model(
    model_path="ai/models/gate_yolov8n.pt", # or "yolov8n.pt" for baseline
    confidence_threshold=0.45,
    iou_threshold=0.50,
    device="cpu" # or "cuda:0"
)
```

### 4.3. Backend REST & WebSocket Contracts (Dhanush $\rightarrow$ Amith)
- **Base URL**: `http://localhost:8000/api`
- **WebSocket URL**: `ws://localhost:8000/ws/monitoring`
- **Video MJPEG Stream**: `http://localhost:8000/api/video/stream`
- **Key Endpoints**:
  - `POST /api/camera/start` — Start camera capture loop.
  - `POST /api/camera/stop` — Stop camera capture loop.
  - `POST /api/camera/source` — Change input source (`webcam` index or recorded video path).
  - `GET /api/monitoring/stats` — Real-time cumulative and today counts (people, vehicles, entries, exits).
  - `GET /api/monitoring/events` — Paginated list of crossing events.
  - `GET /api/analytics/daily` — Aggregate daily traffic breakdown.
  - `GET /api/analytics/hourly` — Aggregate hourly traffic breakdown for peak hour analysis.
  - `GET /api/alerts` — Recent system/security alerts (e.g., unauthorized vehicle, congestion, counterflow).

5. Errors encountered and technical resolutions.
